## Working rules

- Preserve PlatformIO/ESP-IDF and exactly three application C files: `src/main.c`, `src/wifi.c`, `src/flow_sensor.c`; public headers are `include/wifi.h` and `include/flow_sensor.h`. Keep sensor math, benchmark and synthetic tests inside flow_sensor.c, with native tests compiling its portable section. Keep third-party ESP-DSP sources and licensing in components/. All application settings belong in the typed `app` initializer in main.c (`.sensor`, `.wifi`, `.diagnostics`); modules copy the configuration passed to them.
- Sensor input is XIAO ESP32-S3 D10/GPIO9. Normal firmware must never drive that input. Synthetic tests use disconnected D3/GPIO4 and must refuse to use the configured sensor input as the test output.
- The only committed upstream Wi-Fi credentials are the user-approved test hotspot `ABCD` / `00000000` in `app.wifi` in `src/main.c`. Keep WPA2-Personal on 2.4 GHz. Retry five seconds after failures; after 60 seconds without a station IP enable `app.wifi.fallback` as AP+STA: `FlowLab-Local` / `00000000`, http://192.168.4.1. Keep the AP until reboot and keep upstream retries, spaced 30 seconds after failures once fallback is active. This is an IP timeout, not an Internet reachability check; do not add NAT implicitly. The local HTTP routes are read-only and contain no hosting/app tokens. Do not restore enterprise accounts or passwords. Private app and hosting tokens belong in environment variables or ignored instance configuration.
- Flow calibration is unknown: `app.sensor.pulses_per_litre=0`. Keep litres/minute and litres null until calibrated. Distinguish synthetic tests, on-board tests, uploads and physical water-flow accuracy.
- Use PythonAnywhere's authenticated Files and Webapp Reload APIs for source updates. Never expose arbitrary file writes, shell execution or account tokens through the Flask dashboard.
- Maintain device/viewer/admin access boundaries, CSRF checks for browser writes, bounded input, atomic ingestion and idempotent `(device_id, boot_id, seq)` identifiers.
- Schema changes must preserve collected research data. Never reset a deployed database during setup, updates or tests. Keep simulated data labelled.
- After backend changes run `python -m unittest discover -s test/web -v`; after firmware math changes run `python tools/run_host_tests.py`. Build firmware for firmware changes. Check changed dashboard flows on mobile, tablet and desktop when browser tooling is available.
- Package only the web allowlist with `python tools/deploy_pythonanywhere.py bundle`. Do not include instance databases, account configuration, caches or firmware in the upload ZIP.
- Before ending each work session, update the Memory section below with concrete changes, checks and results, current blockers and the next useful action. Replace stale current-state entries; keep the short dated history useful. Do not claim a check passed unless it was run.
