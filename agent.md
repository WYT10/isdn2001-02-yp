## Working rules

- Preserve PlatformIO/ESP-IDF and four application C files: `src/main.c`, `src/wifi.c`, `src/flow_sensor.c`, `src/cli.c`; public headers are `include/wifi.h`, `include/flow_sensor.h`, `include/cli.h`. The user explicitly requested adding cli.c/cli.h, superseding the former three-file limit. Keep sensor math, benchmark and synthetic tests inside flow_sensor.c, with native tests compiling its portable section. Keep third-party ESP-DSP sources and licensing in components/. All default application settings belong in the typed `app` initializer in main.c (`.sensor`, `.wifi`, `.cloud`, `.cli`, `.diagnostics`). The main task owns runtime sensor settings; network mutations run only in the network task. Serial parameter changes are volatile and must not erase NVS or silently persist calibration.
- Supported board defaults are XIAO ESP32-S3 D10/GPIO9 and classic ESP32-WROOM D15/GPIO15. The user changed the WROOM sensor signal to D15, superseding the earlier GPIO27 wiring. Never use the XIAO GPIO9 mapping on WROOM (module flash). Normal firmware must never drive the selected sensor input. Synthetic tests use disconnected GPIO4 (XIAO D3) and must refuse the sensor input as output. WROOM uses UART0 over its USB serial bridge; XIAO uses native USB Serial/JTAG. Keep board/app labels and pin data in the main.c app initializer and readings. Target-specific SDK defaults must stay tracked.
- The only committed upstream Wi-Fi credentials are the user-approved test hotspot `ABCD` / `00000000` in `app.wifi` in `src/main.c`. Keep WPA2-Personal on 2.4 GHz. Retry five seconds after failures; after 60 seconds without a station IP enable `app.wifi.fallback` as AP+STA: XIAO `SensorLab-Local` or WROOM `SensorLab-WROOM`, password `00000000`, http://192.168.4.1. Keep the AP until reboot and keep upstream retries, spaced 30 seconds after failures once fallback is active. This is an IP timeout, not an Internet reachability check; do not add NAT implicitly. The local HTTP routes are read-only and contain no hosting/app tokens. Optional cloud ingestion uses only the device role key from ignored .local/cloud.json; never place viewer/admin/provider account keys on a board. Keep its private generated firmware out of published artifacts. Synthetic self-test builds must disable cloud uploading. Buffering is bounded RAM with explicit drop counters; never claim lossless offline persistence. The user subsequently authorized a private eduroam/PEAP profile. Store its values only in ignored .local/wifi.json and generated .pio/ headers/images, never authored source, public artifacts, dashboards or echoed diagnostics. Preserve trusted CA-bundle, server-domain and certificate-time validation. Default/public builds retain ABCD. Private app and hosting tokens belong in environment variables or ignored instance configuration.
- Flow calibration is unknown: `app.sensor.pulses_per_litre=0`. Keep litres/minute and litres null until calibrated. Distinguish synthetic tests, on-board tests, uploads and physical water-flow accuracy.
- Use PythonAnywhere's authenticated Files and Webapp Reload APIs for source updates. Never expose arbitrary file writes, shell execution or account tokens through the Flask dashboard.
- Maintain device/viewer/admin access boundaries, CSRF checks for browser writes, bounded input, atomic ingestion and idempotent `(device_id, boot_id, seq)` identifiers.
- Schema changes must preserve collected research data. Never reset a deployed database during setup, updates or tests. Keep simulated data labelled.
- After backend changes run `python -m unittest discover -s test/web -v`; after firmware math changes run `python tools/run_host_tests.py`. Build firmware for firmware changes. Check changed dashboard flows on mobile, tablet and desktop when browser tooling is available.
